1. Projekt, WebGPU och WebXR

Målet

Skapa en fristående Three.js-app som renderar spelet i en vanlig webbläsare och kan växla till VR. Vi använder Vite för utvecklingsserver och byggning. Öppna main.js och projektets package.json.

Three.js WebGPURenderer används först. Den kan falla tillbaka till WebGL2 när WebGPU saknas. I Quest Browser väljer appen WebGL2 om webbläsaren inte exponerar XRGPUBinding, eftersom WebXR måste fungera även när kombinationen WebGPU + immersive XR ännu inte stöds. Detta är inte ett avsteg från kursens WebGPU-del: desktop använder WebGPU där det finns; VR använder den renderer-backend som headsetet faktiskt klarar.

renderer = new WebGPURenderer({ antialias: true, forceWebGL: webglFallback });
await renderer.init();
renderer.xr.enabled = true;
renderer.xr.setReferenceSpaceType('local-floor');
document.body.appendChild(VRButton.createButton(renderer));
renderer.setAnimationLoop(tick);

Gör själv

  1. Kör cd web-threejs, npm install, npm run dev.
  2. Öppna http://localhost:4323/ på Macen. Bekräfta att startmenyn och 3D-banan visas.
  3. Öppna kursen på http://localhost:4323/course/index.html.
  4. Läs texten uppe till höger i spelet: den visar om WebGPU eller WebGL2 används.

Varför WebXR behöver HTTPS

WebXR:s immersive-vr är en säker webbfunktion. Vanlig http://<Macens-IP>:4323 i Quest Browser är inte tillräckligt. Använd HTTPS från en riktig host eller ADB port reverse så att Quest Browser når appen som http://localhost:4323/. Se kapitel 8.

Källor: Three.js WebGPURenderer, Three.js VRButton, Meta WebXR.
